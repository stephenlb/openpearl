OpenPearl

Ticket to auto-merge. Minimal GitHub workflow.

OpenPearl reads a ticket, implements it, opens a PR, reviews it in a loop and auto-merges. All as a GitHub workflow. If it isn't confident, it hands the PR to a human.

How it works

When an owner, member, or collaborator opens an issue, .github/workflows/issue-to-pr.yml runs:

  1. The agent implements the issue and opens a PR.
  2. The agent CLI runs two review/fix rounds.
  3. The agent CLI runs the eval in .github/workflows/evals/pr-ready-to-merge.md. On YES the PR is squash-merged; otherwise it stays open for a human.

Install

Paste this prompt into your coding agent (Claude Code, Codex, OpenCode) from the root of your project. It installs the OpenPearl workflow files.

Install OpenPearl into this project.

1. Download the .github/workflows directory from https://github.com/stephenlb/openpearl (branch main) into this project's .github/workflows directory: issue-to-pr.yml and the evals/ folder (evals/pr-ready-to-merge.md). Only also copy jira-to-issue.yml, issue-comment-to-jira.yml and trello-to-issue.yml if I use Jira or Trello. For example: git clone --depth 1 https://github.com/stephenlb/openpearl /tmp/openpearl, then copy the files. Do not overwrite existing files without asking me.
2. Do not modify any other files in my project.
3. Commit the new files on a branch and tell me to finish setup:
   - Enable Settings > Actions > General > "Allow GitHub Actions to create and approve pull requests".
   - Add the secret ANTHROPIC_API_KEY under Settings > Secrets and variables > Actions (or the Amazon Bedrock secrets listed in https://github.com/stephenlb/openpearl#setup).

See the README for setup instructions.
